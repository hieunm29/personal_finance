# 7. Trợ lý AI qua Zalo Bot — Kiến trúc & Giải thích cho người mới

> Mục tiêu: người dùng nhắn Zalo kiểu *"mua cà phê 45k"*, *"nhận lương 20 triệu"*, *"tháng này tiêu bao nhiêu?"* — bot tự ghi giao dịch hoặc trả lời thống kê từ dữ liệu thật trong app.

---

## 1. Bức tranh tổng thể

```
Zalo app ──► Zalo Bot Platform ──POST──► /webhooks/zalo   (channels/zalo/webhook.ts)
                                            │ ① kiểm tra secret  ② chống trùng  ③ trả 200 ngay
                                            ▼
                                  zaloUserId ─► authUserId      (bảng zalo_links)
                                            ▼
                                  runAgent(authUserId, text)    (ai/agent.ts)
                                            │
          system prompt ─┐                  ▼
          danh mục/ví ───┼──► Claude API ◄──► Tool Runner ──► tools (ai/tools/*)
          lịch sử chat ──┘                                      │ gọi service có sẵn
                                                                ▼
                                                     transactionService / reportService / ...
                                            │
                              câu trả lời ──┴──► zaloClient.sendMessage
```

Ba lớp tách biệt, mỗi lớp chỉ biết lớp ngay dưới nó:

| Lớp | Thư mục | Biết gì | Không biết gì |
|---|---|---|---|
| **Channel** | `apps/server/src/channels/zalo/` | Zalo API, webhook, lệnh `/link` | Claude, tools |
| **Agent** | `apps/server/src/ai/` | Claude, prompt, tools, trí nhớ | Zalo |
| **Service** | `apps/server/src/services/` (có sẵn) | Nghiệp vụ, DB | AI |

→ Muốn thêm Telegram hoặc khung chat trên web: chỉ viết thêm 1 channel, gọi lại `runAgent`.

## 2. Các khái niệm AI Engineering (đọc trước khi đọc code)

### 2.1 LLM chỉ sinh chữ
Claude là mô hình ngôn ngữ: nhận văn bản, trả văn bản. Nó **không** tự đọc DB, không tự biết hôm nay ngày mấy, không nhớ cuộc trò chuyện trước. Mọi thứ nó biết phải được ta gửi lên trong mỗi lần gọi API.

### 2.2 Tool use (function calling)
Ta mô tả cho Claude một danh sách **tool**: tên, mô tả, JSON Schema tham số. Khi cần, Claude không trả lời ngay mà trả về:

```json
{ "type": "tool_use", "name": "create_transaction",
  "input": { "type": "expense", "amountVnd": 45000, "categoryId": "…", "note": "Cà phê" } }
```

Code của ta chạy hàm thật, gửi kết quả về (`tool_result`), Claude đọc kết quả rồi viết câu trả lời cho người dùng.

### 2.3 Agent loop
"Gọi Claude → chạy tool → gửi kết quả → gọi Claude lại" lặp đến khi Claude trả lời bằng chữ. Đó là **agent**. SDK có sẵn **Tool Runner** (`client.beta.messages.toolRunner`) chạy vòng lặp này; ta giới hạn tối đa `maxIterations = 6` vòng để không lặp vô hạn.

> Vì sao tự chạy vòng lặp trong server thay vì dùng **Claude Managed Agents** (Anthropic host vòng lặp + container)? Mọi tool ở đây phải chạm SQLite trên server của bạn, mỗi tin nhắn là một lượt ngắn, không cần sandbox → tự host đơn giản và rẻ hơn. Nếu sau này cần agent chạy dài/định kỳ có thể cân nhắc lại.

### 2.4 Memory (trí nhớ)
API là *stateless*: mỗi lần gọi, model chỉ biết những gì ta gửi lên. Bot có 2 loại trí nhớ:

**Ngắn hạn — lịch sử hội thoại** (bảng `ai_messages`): lưu từng lượt chat, gửi lại 20 tin gần nhất (`AI_HISTORY_LIMIT`) để hiểu câu nối tiếp như "còn tháng trước thì sao?". Chỉ lưu chữ cuối cùng, không lưu các bước tool. Tin cũ hơn 20 tin thì "trôi" mất. Lệnh `/reset` xóa loại này.

**Dài hạn — điều người dùng dặn nhớ** (bảng `ai_user_facts`): khi bạn nói "nhớ là cà phê luôn ghi vào ví Momo", model gọi tool `remember_fact` để lưu. Mỗi lần gọi, *toàn bộ* danh sách này được chèn vào system prompt (mục "Điều cần nhớ", kèm id) → không bao giờ trôi mất, `/reset` không xóa. Nói "quên chuyện ví Momo đi" → `forget_fact`.

Vì sao không dùng vector DB / RAG? Mỗi người chỉ vài chục điều (giới hạn 50, mỗi điều ≤ 300 ký tự), chèn thẳng vào prompt là đủ và chính xác hơn tìm kiếm. RAG chỉ cần khi dữ liệu quá lớn để nhét vừa prompt. Số liệu tài chính thì *không* cần nhớ — tool luôn đọc trực tiếp từ DB.

Lưu ý thiết kế:
- Bot **chỉ nhớ khi được yêu cầu**, không tự ý ghi nhớ (tránh lưu nhầm, tránh lưu thông tin nhạy cảm).
- Nội dung đã nhớ do người dùng nói ra, nên được đóng khung là *thông tin tham khảo*, không phải lệnh hệ thống.
- Danh sách nằm trong khối system đã đánh dấu cache: chỉ khi thêm/xóa một điều thì cache khối này mới phải làm lại.
- Guard (mục 2.9) cũng kiểm tra câu "Đã ghi nhớ" / "Đã quên" phải đi kèm lần gọi `remember_fact` / `forget_fact` thật.

### 2.5 System prompt
"Bản mô tả công việc" cho Claude (`ai/prompts/systemPrompt.ts`): vai trò, cách hiểu "45k / 2tr5 / 1 củ", quy tắc ghi luôn rồi nhắc "hoàn tác", không bịa số liệu. Có 2 phần:
1. **Phần cố định** — giống nhau cho mọi người.
2. **Phần theo user** — danh sách danh mục + ví kèm `id`, để Claude chọn `categoryId` mà không tốn thêm 1 lượt gọi tool.

Ngày hôm nay **không** đặt trong system mà gắn vào đầu tin nhắn mới nhất: `[Hôm nay: 2026-11-19]` (lý do: xem 2.6).

### 2.6 Prompt caching
Claude tính phí theo token đầu vào. Phần đầu prompt lặp lại mỗi lần (tools → system) có thể được **cache** (rẻ hơn ~90%, nhanh hơn) nếu nó **giống hệt từng byte**. Vì vậy:
- Đặt `cache_control` ở cuối 2 khối system.
- Thứ tự tool cố định.
- Không chèn giờ/phút hay dữ liệu thay đổi vào system.

Lưu ý: prompt quá ngắn (dưới ngưỡng tối thiểu của model) sẽ không được cache — không lỗi, chỉ không giảm giá. Kiểm tra bằng `usage.cache_read_input_tokens`.

### 2.7 Nhà cung cấp, model & effort
Code luôn dùng **Anthropic SDK** và định dạng Anthropic Messages API. Chọn nơi gửi request bằng `AI_PROVIDER`:

| `AI_PROVIDER` | Key | Model mặc định | Ghi chú |
|---|---|---|---|
| `openrouter` | `OPENROUTER_API_KEY` | `anthropic/claude-opus-5.5` | Endpoint tương thích Anthropic tại `https://openrouter.ai/api`, key gửi qua `Authorization: Bearer` |
| `anthropic` | `ANTHROPIC_API_KEY` | `claude-opus-5-5` | Gọi thẳng Anthropic, có đủ tính năng bên dưới |

- **Tên model khác nhau theo provider**: OpenRouter dùng `vendor/model` với dấu chấm (`anthropic/claude-haiku-5.5`); Anthropic dùng gạch ngang (`claude-haiku-5-5`). Đổi model chỉ cần sửa `AI_MODEL`, xem danh sách tại openrouter.ai/models.
- **Chỉ có khi `AI_PROVIDER=anthropic`** (`aiConfig.anthropicExtras`): `effort` (mức "suy nghĩ"), `fallbacks: "default"` (tự chạy lại trên model dự phòng nếu bộ lọc an toàn từ chối nhầm), và *message threads* (Tool Runner chỉ gửi phần tin mới mỗi vòng). Với OpenRouter các tính năng này bị tắt và mỗi vòng gửi lại toàn bộ hội thoại (`thread: false`).
- **Model không phải Claude** qua OpenRouter (GLM, Kimi, GPT…) có thể chạy được nhưng không đảm bảo: khả năng gọi tool và hiểu tiếng Việt khác nhau → cần thử lại các câu mẫu ("cà phê 45", "hoàn tác") trước khi dùng thật.

### 2.8 Bảo mật — ranh giới quan trọng nhất
`authUserId` **không bao giờ** là tham số của tool. Nó được server xác định từ `zalo_links` rồi "đóng gói" vào tool qua `ToolContext`. Dù ai nhắn "xem dữ liệu của user khác", model cũng không có đường nào truyền userId khác. Test `aiAssistant.test.ts` kiểm tra user B không thấy giao dịch của user A.

Webhook xác thực bằng header `X-Bot-Api-Secret-Token` (so sánh constant-time). Người chưa liên kết **không** được gọi AI (không tốn tiền, không lộ dữ liệu).

### 2.9 Chống "bịa" (hallucination guard)
LLM có thể **nói** "Đã ghi…" mà **không gọi tool** — chuyện đã xảy ra thật khi dùng `minimax/minimax-m3`: bot báo đã ghi lương 28 triệu, rồi báo tổng thu 28 triệu, trong khi DB không có gì. Prompt không đủ để ngăn, nên có 3 lớp trong code (`ai/guard.ts`):

1. **Nhật ký tool thật** — mỗi tool được bọc (`withCallLog` trong `ai/tools/index.ts`) để ghi lại lần chạy thành công/lỗi. Đây là nguồn sự thật do server nắm, không phải lời model.
2. **Đối chiếu câu trả lời** (`checkReply`): nói "Đã ghi / Đã hoàn tác" mà không có lần `create_transaction` / `undo_last_action` thành công, hoặc đưa ra số tiền mà không gọi tool nào → cho model làm lại **1 lần** kèm lời nhắc `[Hệ thống kiểm tra]`. Vẫn sai → `finalizeReply` thay bằng "mình CHƯA ghi được…".
3. **Lịch sử kèm hành động thật** — mỗi câu trả lời được lưu kèm dòng `[Hệ thống ghi nhận: create_transaction thành công (id …)]` hoặc `[… không gọi công cụ nào]`, để model không học theo kiểu "chỉ nói mà không làm". Dòng này bị lọc khỏi tin gửi người dùng.

Bài học AI Engineering: **đừng tin lời model về những gì nó đã làm** — kiểm tra bằng dữ liệu mà code nắm. Model mạnh hơn (Claude) ít mắc lỗi này hơn, nhưng guard vẫn cần cho mọi model.

## 3. Luồng ví dụ: "mua cà phê 45k"

1. Zalo gửi `POST /webhooks/zalo` với `event_name = message.text.received`.
2. Webhook kiểm tra secret, ghi `message_id` vào `zalo_processed_messages` (Zalo gửi lại → bỏ qua), trả `200` ngay.
3. Hàng đợi theo từng user xử lý nền: tra `zalo_links` → `authUserId`; gửi "đang soạn tin…".
4. `runAgent` dựng request: system (cố định + danh mục/ví) + 20 tin cũ + `[Hôm nay: 2026-11-19]\nmua cà phê 45k`.
5. Claude trả `tool_use create_transaction {type: expense, amountVnd: 45000, categoryId: <Ăn uống>, note: "Cà phê"}`.
6. Tool đổi 45000 → 4.500.000 cents, chọn ví mặc định, gọi `createTransaction` có sẵn, ghi `ai_actions` (để hoàn tác).
7. Claude đọc kết quả, trả lời: *"Đã ghi chi 45.000đ – Ăn uống (Tiền mặt). Gõ hoàn tác nếu sai."*
8. Lưu lượt chat vào `ai_messages`, gửi trả lời qua `sendMessage` (tự cắt nếu > 2000 ký tự).

## 4. Danh sách tools

| Tool | Gọi service | Ghi chú |
|---|---|---|
| `create_transaction` | `createTransaction` | VND → cents; ví mặc định nếu không nói; kiểm tra danh mục đúng loại |
| `undo_last_action` | `deleteTransaction` | Xóa giao dịch AI ghi gần nhất chưa hoàn tác |
| `search_transactions` | `getTransactions` | Tối đa 20 dòng + tổng thu/chi |
| `get_monthly_summary` | `getMonthlyOverview`, `getExpensesByCategory` | Top 10 danh mục |
| `get_budget_status` | `getBudgetProgress` | |
| `get_net_worth` | `getAssetOverview` | |
| `create_transfer` | `createTransfer` | Chuyển giữa 2 tài khoản tiền mặt/ngân hàng (rút ATM, nộp tiền); không tính thu/chi; hoàn tác được |
| `remember_fact` | `addFact` (memory.ts) | Lưu 1 điều người dùng dặn nhớ; tối đa 50 điều, ≤ 300 ký tự |
| `forget_fact` | `deleteFact` (memory.ts) | Xóa theo id; luôn lọc theo user |

Lỗi nghiệp vụ trong tool được ném ra → Tool Runner gửi về Claude với `is_error: true` → Claude tự sửa (chọn danh mục khác) hoặc hỏi lại người dùng.

**Thêm tool mới**: tạo `betaTool({ name, description, inputSchema, run })` trong `ai/tools/`, thêm vào `buildTools`. Viết `description` thật rõ *khi nào* dùng — đó là thứ duy nhất Claude đọc để quyết định.

## 6. Cấu trúc file

```
apps/server/
├── src/ai/
│   ├── config.ts            # đọc env: model, effort, historyLimit
│   ├── client.ts            # Anthropic SDK; đổi baseURL/key khi dùng OpenRouter
│   ├── agent.ts             # runAgent — vòng lặp Tool Runner, xử lý lỗi/refusal
│   ├── guard.ts             # chống bịa: đối chiếu câu trả lời với tool đã chạy thật
│   ├── memory.ts            # ngắn hạn: loadHistory/saveTurn/clearHistory; dài hạn: loadFacts/addFact/deleteFact
│   ├── userContext.ts       # danh mục + ví của user, profileId ↔ authUserId
│   ├── prompts/systemPrompt.ts
│   ├── tools/{index,helpers,transactionTools,reportTools,memoryTools}.ts
│   └── aiAssistant.test.ts  # test không gọi Claude thật
├── src/channels/zalo/
│   ├── zaloClient.ts        # sendMessage, sendChatAction, setWebhook
│   ├── linking.ts           # mã liên kết, tra cứu zalo_links
│   └── webhook.ts           # POST /webhooks/zalo
├── src/routes/integrations.ts  # /api/integrations/zalo/* (cần đăng nhập)
└── scripts/
    ├── ai-chat.ts           # chat thử trên terminal
    └── zalo-set-webhook.ts  # đăng ký webhook với Zalo
```

## 7. Chạy thử

### 7.1 Cấu hình `.env`
```
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=sk-or-...
AI_MODEL=anthropic/claude-haiku-5.5   # bỏ trống = anthropic/claude-opus-5.5
ZALO_BOT_TOKEN=...            # tạo bot tại Zalo Bot Platform
ZALO_WEBHOOK_SECRET=...       # chuỗi ngẫu nhiên tự đặt
PUBLIC_BASE_URL=https://xxx.trycloudflare.com
```

### 7.2 Thử AI không cần Zalo (gọi model thật — tốn phí, ghi DB thật)
```bash
cd apps/server && bun run db:migrate
bun run ai:chat you@example.com "mua cà phê 45k"
bun run ai:chat you@example.com "tháng này tiêu bao nhiêu?"
bun run ai:chat you@example.com "hoàn tác"
```

### 7.3 Nối với Zalo
```bash
cloudflared tunnel --url http://localhost:3000   # lấy URL public → PUBLIC_BASE_URL
bun run zalo:webhook                              # đăng ký webhook
```
Lấy mã liên kết (chưa có UI, dùng API khi đang đăng nhập trên web):
`POST /api/integrations/zalo/link-code` → nhắn bot: `/link ABC123`.

### 7.4 Test tự động
```bash
cd apps/server && bun test src/ai
```

## 8. Hướng mở rộng (chưa làm)
- UI "Liên kết Zalo" trong trang Cài đặt (cần duyệt layout theo prototype).
- Ảnh hóa đơn (Claude đọc ảnh — vision), tin nhắn giọng nói.
- Ghi mua tài sản (vàng, cổ phiếu) qua chat.
- Bot chủ động nhắc khi vượt ngân sách / báo cáo cuối tuần.
- Bộ **eval**: tập ~50 câu chat mẫu + kết quả mong đợi, chạy lại mỗi khi sửa prompt để biết bot tốt lên hay tệ đi.
- Ghi log `usage` (token, cache hit) để theo dõi chi phí.
